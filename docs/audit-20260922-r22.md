# FakeSIP r22 release audit

Date: 2026-09-22 (Asia/Taipei)
Initial audit base: `b1c5c07`; release integration base: `92f44e3`.
Status: synchronized r22 APKs installed and verified on OpenWrt 25.12.5 x86_64.

## Confirmed defects and fixes

### UDP checksum zero encoding

Both packet builders passed through a zero result from libnetfilter_queue.
For IPv6 this produces an invalid ordinary UDP packet; for IPv4 it means no
checksum instead of the computed checksum. Both builders now encode a computed
zero as `0xffff`, as required by [RFC 768](https://www.rfc-editor.org/rfc/rfc768)
and [RFC 8200 section 8.1](https://www.rfc-editor.org/rfc/rfc8200#section-8.1).

An independent checksum test enumerates all 65,536 two-byte payload values for
each address family and also covers empty and odd-length payloads: 131,076
generated packets in total. Before the fix, IPv4 payload `fba6` and IPv6 payload
`066a` triggered zero checksums with the test's fixed addresses and ports.
After the fix, all wire lengths, checksums and parser round trips pass.

### Subprocess pipe descriptor collisions

If standard descriptors are closed, `pipe()` can return descriptor 0, 1 or 2.
The old child setup could overwrite or close a pipe end during output/input
redirection. A normal subprocess with supplied input then failed. The fix moves
only these low-numbered pipe descriptors above stderr before forking.

The regression covers all eight standard-descriptor open/closed combinations,
both silent output and logfile redirection, checks the child's input and output,
and retains the existing broken-pipe failure test. Seven closed-descriptor
combinations failed in silent mode before the fix. All 16 combinations now pass.

## Verification

Fresh local Debian/WSL checks:

- GCC 14 debug build; full CLI/core regression with ASan/LSan/UBSan and fatal UBSan.
- GCC `-fanalyzer -Werror` build.
- OpenWrt init, LuCI behavior, all 76 Traditional Chinese messages and package smoke.
- nftables and iptables partial-setup rollback in isolated network namespaces.
- Ten actual process start/stop cycles across both `-0` and `-1`, with IPv4 and
  IPv6 traffic over a veth pair between isolated namespaces. Each probe receives
  exactly one original datagram, one original reply and one SIP decoy. Queue
  backlog/kernel drops/user drops stay zero; SIGTERM exits normally and removes
  rules/queue ownership. Observed sanitizer-build stop times: about 51-83 ms.

The runtime regression is `tools/linux-runtime-smoke-test.sh`; it requires Linux,
root, Node.js, iproute2, util-linux, nftables, and a built FakeSIP binary. Run it
with `bash tools/linux-runtime-smoke-test.sh` or set `FAKESIP` to a candidate binary.
It creates private network namespaces and does not change host firewall rules.

No crash, sanitizer finding, original-packet duplication, queue drop, or forced
shutdown was observed in the successful test windows. This is not long-run or
throughput evidence.

## Test limitations and harness corrections

- The first integration attempt lost temporary build files between WSL command
  sessions; subsequent builds and logs use persistent private build storage.
- An early loopback-only test could not receive the `-1` AF_PACKET output through
  a UDP socket. The final test uses two veth-connected namespaces and passes both
  directions. The loopback failure is not counted as router failure evidence.
- An initial descriptor-redirection fix failed the added logfile cases and was
  replaced with descriptor relocation. GCC analyzer and sanitizer tests validate
  the final implementation.
- General ShellCheck reports existing platform-specific/script warnings; the new
  runtime harness is checked separately. Historical warnings are not claimed fixed.
- The copied workspace contains invalid Git checkpoint references that prevent a
  normal fetch. Release preparation uses a fresh clone and only the audited changes.
- The OpenWrt SDK's libnetfilter_queue UDP header emits cross-family forward
  declaration warnings. Target regression builds use the normal release warning
  policy; the separate Debian analyzer build passed with `-Werror`.

## Publication requirements

Use the existing pseudonymous fork and `Codex <codex@local.invalid>` for both
author/committer and annotated tagger. Publish only the OpenWrt 25+ core/LuCI APKs
and `SHA256SUMS`. Scan source, added documentation, commit/tag identity, package
metadata and extracted contents for personal paths, private endpoints and secrets.
Keep rollback archives and device logs private. Do not use a server-created merge
that substitutes an account-linked email.

The final snapshot scan also decodes Base64 handoffs and checks both known access
passwords without storing them in source. Old private path/alias references were
redacted and companion encodings synchronized. Source, decoded documents, APK
metadata and extracted contents passed the scan. New commits and the annotated
tag use the anonymous identity. Historical public Git objects are not rewritten.
